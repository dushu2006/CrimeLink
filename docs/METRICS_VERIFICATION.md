# Metrics Verification — Alert Rules vs Real Emitted Metrics

**Date:** 2026-09-15
**Issue raised:** Agent-written monitoring configs often have alert YAML that looks correct but references metrics nobody emits — Prometheus silently never fires them.

## Verification Method

```bash
grep -R "crimelink_" backend/app/services/metrics.py -n
# And check render_metrics() exposition
python -c "from app.services.metrics import render_metrics; print(render_metrics()[0].decode())"
```

## Previously Missing Metrics — Fixed

**Before fix (commit ce3c55d):**
- `crimelink_audit_verification_failures_total` — referenced in alert_rules.yml but NOT defined in metrics.py → alert would never fire
- `crimelink_db_health_ok` — referenced but NOT defined → alert would never fire

**After fix (this commit):**
- Added `AUDIT_VERIFICATION_FAILURES` Counter in metrics.py
- Added `DB_HEALTH` Gauge in metrics.py
- Wired `AUDIT_VERIFICATION_FAILURES.inc()` in `audit/service.py` verify() and verify_async() on failure
- Wired `DB_HEALTH.set()` in `refresh_gauges()` based on graph_ok && db_ok
- Verified via `render_metrics()` exposition: both now appear

```
crimelink_audit_verification_failures_total 0.0
crimelink_db_health_ok 0.0
crimelink_audit_rows 0.0
...
```

## Alert Rules Verification

`infra/monitoring/alert_rules.yml` after fix:

- **CeleryQueueGrowing:** `sum(increase(crimelink_documents_processed_total[5m])) == 0 and crimelink_er_queue_pending > 10` — both metrics verified, sum() added because counter has label document_type
- **QuarantineSpike:** `sum(increase(crimelink_documents_failed_total[15m])) > 10` — verified
- **PatternQueueBacklog:** `crimelink_pattern_queue_new > 50` — verified gauge
- **EntityResolutionSLABreach:** `crimelink_er_queue_oldest_item_hours > 48` — verified gauge, SLA 48h per PRD 7.3
- **EntityResolutionQueueHigh:** `crimelink_er_queue_pending > 100` — verified
- **HighAPIErrorRate:** `sum(rate(crimelink_api_requests_total{status=~"5.."}[5m])) > 0.05` — verified counter with labels, sum() across method/path
- **APILatencyHigh:** `histogram_quantile(0.95, sum by (le) (rate(crimelink_api_request_duration_seconds_bucket[5m]))) > 2` — verified histogram, _bucket auto-generated by prometheus_client
- **RateLimitingHigh:** `sum(increase(crimelink_api_requests_total{status="429"}[5m])) > 20` — verified, RateLimitError returns 429
- **AuditChainVerificationFailed:** `increase(crimelink_audit_verification_failures_total[5m]) > 0` — **NOW VERIFIED** after adding metric
- **AuditLogGrowthStalled:** `delta(crimelink_audit_rows[30m]) == 0` — verified gauge, delta works for monotonic gauge
- **DatabaseHealthUnhealthy:** `crimelink_db_health_ok == 0` — **NOW VERIFIED** after adding metric
- **GraphNodesUnusualDrop:** `delta(crimelink_graph_nodes[10m]) < -100` — verified gauge

## Scrape Path Fix

- **Before:** `prometheus.yml` used `metrics_path: "/api/v1/health/metrics"` — **WRONG**, no such endpoint. Real endpoint is `/api/v1/metrics` (see `backend/app/api/v1/health.py` `GET /metrics` and `main.py` `app.include_router(api_router, prefix="/api/v1")`)
- **After:** Fixed to `/api/v1/metrics`

## How to Re-Verify

```bash
# 1. Check metrics.py defines all names referenced in alert_rules.yml
grep -E "crimelink_[a-z_]+" backend/app/services/metrics.py

# 2. Check alert_rules.yml references
grep -E "crimelink_[a-z_]+" infra/monitoring/alert_rules.yml

# 3. Run exposition
python -m app.services.metrics  # or via /api/v1/metrics endpoint

# 4. Check Prometheus targets
curl http://localhost:9090/api/v1/targets | jq

# 5. Check Prometheus rules
curl http://localhost:9090/api/v1/rules | jq
# All rules should show "health": "ok", not "no data"
```

All alert rules now reference real, currently-emitted metrics. No silent no-op alerts.
